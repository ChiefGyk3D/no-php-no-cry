# Privacy page and analytics (issues 62 and 84)

`/privacy/` (`content/privacy/index.md`) says what the repository can establish:
the site code sets no cookies and embeds nothing from other sites. The owner
confirmed on 2026-11-07 that Cloudflare Web Analytics is turned on for the Pages
project, so the page says so and quotes Cloudflare's own description of what it
collects (developers.cloudflare.com/web-analytics/about, data-origin-and-collection
and dimensions, read 2026-11-07). The owner then decided to allow the beacon:
`static/_headers` now carries `script-src 'self'
https://static.cloudflareinsights.com/beacon.min.js` and `connect-src 'self'`,
the two entries Cloudflare's FAQ (web-analytics/faq, "What do I need to add to
my Content Security Policy", last updated Jul 14, 2026) names for automatic
injection. Pages adds the beacon at the edge on the next deployment after the
toggle (pages/how-to/web-analytics, Apr 21, 2026), so it never appears in built
HTML and the build checks still reject any other script element. The page does
not describe what Cloudflare logs on its own. `scripts/test-pages.sh` rejects
"collect nothing", "no analytics" and "likely block" claims (issue 159).

The collector is built but not deployed (issue 84): see
`docs/analytics-deploy.md`. The replacement text is drafted in
`docs/privacy-with-analytics.md` and goes live with the first deploy that binds
the database.

## Support page notes (issue 62)

- Wallet addresses live in `data/support.yaml`, copied verbatim from the public
  repo github.com/ChiefGyk3D/support-me (SIGNATURE.md), which stays the source
  of truth. The QR files in `static/support/` are pre-generated by
  `scripts/gen-support-qr.sh` (segno 1.6.6, pinned with a hash in
  `scripts/requirements-qr.txt`); `scripts/gen-support-qr.sh --check` verifies
  them. Change an address in all three places in one pull request: the data
  file, the QR files and `scripts/test-pages.sh`.
- The site ships two pinned scripts, each on one page only (see
  `docs/pinned-script.md`). Copy buttons on /support/ use `/copy.js` (issue 95);
  site search on /search/ uses `/search.js` (issue 119), which filters the list
  already on the page. Neither does a network request, uses cookies or storage
  (no localStorage, no sessionStorage), or sends what you type anywhere: the
  query is never submitted (there is no form) and the address is never rewritten.
  A third pinned script is a separate change to the allowlist, the hash files,
  `check-output.sh`, `check-site-artifact.sh`, `smoke-site.sh` and their tests.
- Ko-fi is a link-out. An embed facade needs `frame-src https://ko-fi.com`, which
  waits on a real-browser framing test. StreamElements and Patreon refuse framing.
